# Средства и технологии разработки

| Средство/технология разработки | Аргументы в пользу выбора |
|---|---|
| **Python 3.12** (язык программирования) | Стандарт де-факто для быстрой разработки backend-систем: выразительный синтаксис, богатая экосистема библиотек для ORM, валидации и тестов. В проекте уже используется: весь бизнес-слой (`app/`), 50 автотестов проходят на CI. Сильная типизация (`typing`, `Mapped[]`) позволяет отражать UML-классы в коде один в один. |
| **FastAPI** (web-фреймворк) | Асинхронность и высокая производительность на уровне Starlette; автоматическая генерация OpenAPI/Swagger-документации из типизированных сигнатур — требование BR-22.1 («документируемость API») выполняется «бесплатно». Встроенная валидация входных данных через Pydantic снижает риск ошибок входа. Схема зависимостей (`Depends`) даёт чистое разграничение прав по ролям (BR-03). |
| **Uvicorn** (ASGI-сервер) | Стандартный production-сервер для FastAPI на базе uvloop/h11, обеспечивает работу WebSocket (BR-20) и health-check в Docker. Минимальные накладные расходы, официально рекомендован документацией FastAPI. |
| **PostgreSQL 15** (СУБД) | Требования к целостности данных (BR-22.6) закрыты на уровне СУБД: CHECK-ограничения статусов, внешние ключи, частичные уникальные индексы (`WHERE status='CREATED'`) — без них невозможно правило «одно активное бронирование на клиента/авто» (BR-05). Плюс JSONB для деталей аудита (BR-19), геометрия для зон (BR-12), транзакционность списаний (BR-15). |
| **SQLAlchemy 2.0** (ORM) | Объечно-реляционное отображение 12 таблиц: классы `Client`, `Car`, `Booking`, `Rental`… являются прямой реализацией диаграммы классов. Аннотации типов `Mapped[]` связывают UML-атрибуты с кодом, `relationship()` описывает связи диаграммы. Снимает ручную работу с SQL и делает код переносимым (SQLite в тестах, PostgreSQL в проде). |
| **Alembic** (миграции) | Эволюция схемы БД без потери данных (BR-22.5): версионированные ревизии (`001_initial_schema`, добавление `lat/lng`, `rate_km` и др.), воспроизводимое развёртывание в Docker и CI, возможность отката. |
| **Pydantic 2** (валидация) | Схемы запросов/ответов (`app/schemas/*`) — единый источник правды для валидации и документации API. Гарантирует, что во внутренний слой не попадут некорректные данные (суммы, даты, перечисления), что критично для финансовых операций (BR-14). |
| **python-jose + passlib (bcrypt)** (аутентификация) | JWT access/refresh-токены — стандарт для stateless REST API (BR-21); bcrypt — стойкое к перебору хэширование паролей с солью. Решение проверенное и широко аудируемое, в отличие от самописной криптографии. |
| **slowapi** (rate limiting) | Прямое закрытие BR-21: 10 запросов/мин на регистрацию, 5/мин на вход по IP — защита от перебора паролей и credential stuffing без написания собственного middleware. |
| **pytest + pytest-asyncio + httpx** (тестирование) | Единый инструмент для unit- и API-тестов; фикстуры дают изоляцию на in-memory SQLite, `httpx` тестирует FastAPI-приложение напрямую без запуска сервера. В проекте — 50 тестов (аутентификация, брони, аренды, безопасность), что подтверждает требование BR-22.3. |
| **Ruff** (линтинг) | Один инструмент вместо flake8/isort/pyupgrade: скорость работы на порядки выше, единый стиль, проверка в CI до мержа. |
| **React 19 + TypeScript** (frontend) | Типизированный UI-слой: типы API-контрактов (`src/lib/api-types.ts`) синхронизируются с Pydantic-схемами, ошибки компиляции ловятся на этапе сборки. React 19 — актуальный стейт-менеджмент для SPA с картой автомобилей и дашбордами. |
| **Vite + Bun** (сборка и менеджер пакетов) | Vite даёт мгновенный HMR и быструю production-сборку; Bun на порядок быстрее npm/yarn при установке зависимостей и запуске скриптов — ускоряет CI-шаг `frontend-build`. |
| **TanStack Router + TanStack Start** (роутинг) | Файловая система маршрутов (`src/routes/*.tsx`) с типобезопасными ссылками и вложением layout (`client.*`, `staff.*`, `auth.*`) — разграничение клиентской и админ-частей на уровне маршрутизации. SSR-поддержка TanStack Start улучшает первую отрисовку. |
| **shadcn/ui + Tailwind CSS 4** (UI-kit) | Компоненты копируются в проект (нет зависимости от чужого репозитория) и полностью редактируются; Tailwind ускоряет разработку адаптивных экранов дашборда, унифицирует дизайн-систему между 20+ страницами. |
| **Recharts + Leaflet + jsPDF** (визуализация) | Recharts — декларативные графики для отчётов (BR-18); Leaflet — отображение автомобилей и зон на карте (BR-04, BR-12) без платных API-ключей; jsPDF — экспорт отчётов в PDF прямо в браузере. |
| **WebSocket (FastAPI + клиентский хук)** (реалтайм) | Закрывает BR-20: мгновенная доставка событий об отмене бронирований и статусах всем подписчикам; `ws_manager` с broadcast уведомляет и клиентов, и операторов без опроса сервера. |
| **Docker + Docker Compose** (контейнеризация) | Воспроизводимое окружение (BR-22.4): идентичные версии Python/PostgreSQL/Node локально, в CI и на сервере; healthcheck и порядок старта сервисов описаны декларативно; исключает «работает у меня». |
| **GitHub Actions + GHCR** (CI/CD) | Автоматический прогон тестов, линтинга и сборки фронтенда на каждый push/PR; при теге `v*` — сборка образов в GHCR и деплой по SSH. Сокращает время выхода в прод и исключает релиз с непрошедшими тестами. |
| **Alembic/pytest в Makefile + `.env` (pydantic-settings)** (конфигурация) | Единые команды (`make`) и типизированное чтение переменных окружения: секреты не попадают в репозиторий, поведение различается между dev/prod без правки кода. |
| **OpenAPI-контракт (`openapi.json`) + Swagger UI** (интерфейсная документация) | Фронтенд и внешние потребители работают по формальному контракту; `/docs` даёт интерактивное исследование API — снижает стоимость интеграции и поддержки. |
| **UML-нотация (PlantUML / Mermaid)** (моделирование) | Диаграммы вариантов использования и классов хранятся как текст рядом с кодом (`docs/uml/*.puml`), версионируются в git и перерисовываются автоматически при изменениях модели. |

## Примечание о соответствии диаграммы классов и реализации

UML-диаграмма классов (`docs/class-diagram.md`, `docs/uml/class-diagram.puml`) реализована на языке **Python** в модуле `app/models/`:

| UML-класс | Файл реализации |
|---|---|
| `Client` | `app/models/clients.py` |
| `Staff` | `app/models/staff.py` |
| `Car` | `app/models/cars.py` |
| `Zone` | `app/models/zones.py` |
| `Tariff` | `app/models/tariffs.py` |
| `Booking` | `app/models/bookings.py` |
| `Rental` | `app/models/rentals.py` |
| `Payment` | `app/models/payments.py` |
| `Discount` | `app/models/discounts.py` |
| `ClientDiscount` | `app/models/client_discounts.py` |
| `Maintenance` | `app/models/maintenance.py` |
| `AuditLog` | `app/models/audit_log.py` |

Поведение классов распределено по сервисному слою: `app/api/v1/rentals.py` (расчёт стоимости, пауза/возобновление), `app/api/v1/bookings.py` (бронирование с TTL), `app/services/booking_expirer.py` (истечение броней), `app/services/audit_service.py` (журнал действий).

**Проверка работоспособности реализации:** `python3 -m pytest tests/ -v` → **50 passed**.
